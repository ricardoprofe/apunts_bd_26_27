1. Tipus de dades en MySQL

En MySQL, hi ha diversos tipus de dades que podem utilitzar per a definir les columnes de les nostres taules. A continuació, es mostren els principals:

MySQL Data Types

1.1. Tipus numèrics

Els tipus numèrics es poden classificar en enters i decimals. Els enters són números sense decimals, mentre que els decimals són números amb decimals.

Per als enters, podem utilitzar els tipus TINYINT, SMALLINT, MEDIUMINT, INT i BIGINT. Aquests tipus de dades tenen diferents rangs de valors que poden emmagatzemar.

Els enters poden ser UNSIGNED, és a dir, només poden emmagatzemar valors positius. Per exemple, un TINYINT UNSIGNED pot emmagatzemar valors entre 0 i 255. Per defecte, els enters són SIGNED, és a dir, poden emmagatzemar valors positius i negatius.

Per a valors monetaris en els quals és important la precisió, és millor utilitzar el tipus DECIMAL(m, d), on m és el nombre total de dígits i d és el nombre de dígits després del punt decimal. Per exemple, DECIMAL(10, 2) pot emmagatzemar números amb fins a 10 dígits en total, dels quals 2 són decimals.

El tipus BOOL o BOOLEAN és un tipus especial que només pot emmagatzemar els valors TRUE (1) o FALSE (0).

1.2. Tipus de text

  • CHAR(n) ocupa sempre n caràcters, encara que no s'utilitzen tots. Per exemple, si definim una columna com CHAR(10) i inserim la paraula "hola", MySQL emmagatzemarà "hola " (amb 6 espais en blanc al final).
  • VARCHAR(n) ocupa només els caràcters que s'utilitzen. Per exemple, si definim una columna com VARCHAR(10) i inserim la paraula "hola", MySQL emmagatzemarà només "hola" (sense espais en blanc al final).
    CHAR i VARCHAR

Utilitzarem CHAR quan sapiguem que totes les dades tindran la mateixa longitud, com per exemple un codi postal. En canvi, utilitzarem VARCHAR quan les dades poden tenir longitud variable, com per exemple un nom o una adreça.

El tipus TEXT s'utilitza per a emmagatzemar grans quantitats de text, com per exemple un article o un comentari. Aquest tipus de dades pot emmagatzemar fins a 65.000 caràcters.

1.3. Tipus de data i hora

  • DATE guarda dates en el format any-mes-dia ('0000-00-00').
  • TIME guarda les hores en el format hora:minuts:segons ('00:00:00'). Amb la funció DATE_FORMAT() es pot mostrar en format AM i PM.
  • DATETIME o TIMESTAMP guarden la data i l'hora en el format any-mes-dia hora:minuts:segons ('0000-00-00 00:00:00').
  • YEAR guarda l'any en 4 dígits.

DATETIME i TIMESTAMP són molt similars, però hi ha algunes diferències importants. DATETIME mostra els valors en format 'YYYY-MM-DD HH:MM:SS'. TIMESTAMP emmagatzema els valors com un nombre enter que representa el nombre de segons des del 1 de gener de 1970 (epoch).

1.4. El tipus BLOB

Un BLOB (Binary Large Object) és un tipus de dades que s'utilitza per a emmagatzemar grans quantitats d'informació binària, com ara imatges, sons o vídeos. Els BLOBs poden ser de diferents tipus segons la seua grandària:

  • TINYBLOB: fins a 255 bytes.
  • BLOB: fins a 65.535 bytes (64 KB).
  • MEDIUMBLOB: fins a 16.777.215 bytes (16 MB).
  • LONGBLOB: fins a 4.294.967.295 bytes (4 GB).

2. Creació i modificació de taules

El DDL de MySQL permet crear i modificar taules amb instruccions específiques. A continuació, es mostren les instruccions bàsiques per a crear i modificar taules:

Instrucció Descripció Referència
CREATE TABLE Crea una nova taula amb les columnes i tipus de dades especificats. CREATE TABLE
ALTER TABLE Modifica una taula existent, afegint, eliminant o canviant columnes, així com afegint o eliminant claus primàries i foranes. ALTER TABLE
DROP TABLE Elimina una taula existent i totes les dades que conté. DROP TABLE
TRUNCATE TABLE Elimina totes les dades d'una taula, però manté la seua estructura. TRUNCATE TABLE
RENAME TABLE Canvia el nom d'una taula existent. RENAME TABLE

També disposem d'instruccions per a visualitzar la informació de les taules, com ara:

Instrucció Descripció Referència
SHOW TABLES; Mostra les taules que hi ha en la base de dades actual. SHOW TABLES
DESCRIBE o DESC nom_taula; Mostra la informació de les columnes d'una taula, com ara el nom, tipus de dades, si pot ser nul·la, si és clau primària, etc. DESCRIBE
SHOW CREATE TABLE nom_taula; Mostra la instrucció SQL que es va utilitzar per a crear una taula, incloent les claus primàries i foranes. SHOW CREATE TABLE

Motors d’emmagatzematge de MySQL

MySQL permet utilitzar diferents motors d’emmagatzematge per a les taules. Els més comuns són:

  • InnoDB: és el motor d’emmagatzematge per defecte en MySQL. Permet transaccions, claus foranes i bloqueig a nivell de fila.
  • MyISAM: és un motor d’emmagatzematge més antic que InnoDB. No permet transaccions ni claus foranes, però és més ràpid en algunes consultes.

Per a especificar el motor d’emmagatzematge d’una taula, podem utilitzar la següent sintaxi:

1
2
3
CREATE TABLE nom_taula (
    ...
) ENGINE=InnoDB;

2.1. Creació de taules

La sintaxi bàsica per a crear una taula és la següent:

1
2
3
4
5
6
7
CREATE TABLE nom_taula (
    nom_columna1 tipus_dada1 [restriccions],
    nom_columna2 tipus_dada2 [restriccions],
    ...
    PRIMARY KEY (nom_columna1),
    FOREIGN KEY (nom_columna2) REFERENCES altra_taula(nom_columna_referenciada)
);

Els noms (de taules, camps, etc) han de començar per lletra i no poden contindre espais o caràcters de puntuació especials.

A banda del tipus de dades, podem indicar restriccions per a cada columna. Les restriccions més comunes són:

  • NOT NULL: indica que la columna no pot tindre valors nuls.
  • DEFAULT valor: indica un valor per defecte per a la columna.
  • AUTO_INCREMENT: indica que la columna és un enter que s'incrementa automàticament amb cada nou registre. Només es pot utilitzar en una columna amb tipus de dades enter.
  • PRIMARY KEY: indica que la columna és la clau primària de la taula.
  • UNIQUE: indica que la columna ha de tindre valors únics. És a dir, no poden haver dos registres amb el mateix valor en aquesta columna.

2.1.2. Creació de taules amb claus primàries i alternatives

Quan creem una taula, si volem indicar que un camp és clau primària utilitzarem PRIMARY KEY. Per a indicar que és clau alternativa, usarem: UNIQUE.

La clau primària i/o les claus alternatives també es poden indicar després de l’última columna:

També podem posar noms a les restriccions (que han de ser únics en tota la base de dades). Una utilitat és poder esborrar després una restricció indicant el seu nom:

2.1.3. Creació de taules amb claus alienes

Cal utilizar el motor d’emmagatzematge InnoDB per a poder utilitzar claus foranes. Per defecte, MySQL utilitza el motor InnoDB, per tant no cal indicar-ho.

Hem d'utilitzar la instrucció FOREIGN KEY per a indicar que una columna és una clau forana. Aquesta instrucció ha d’anar després de l’última columna de la taula.

    tel VARCHAR(15),

1
2

DELETE FROM poble WHERE cpo = 46701;      // Error per la clau aliena, existeix un registre a la taula client amb poble=46701

2.2. Restriccions de les claus foranes

Quan definim una clau forana, podem especificar que, si s’esborra un registre de la taula pare (la de pobles), s’esborren també, automàticament, els registres relacionats de la taula filla (és a dir: que s’eliminen també els clients d’eixe poble).

O bé, podem indicar que, quan modifiquem un codi postal en la taula de pobles, que també es modifique eixe codi en els corresponents clients que tenien eixe poble.

Eixes dos coses (i més) es poden fer posant-ho en la restricció de clau aliena de la taula. Per exemple:

1
2
3
4
5
6
7
8
9
CREATE TABLE client (
    codi INT PRIMARY KEY, 
    nom VARCHAR (40) NOT NULL, 
    poble INT,
    tel VARCHAR(15),
    FOREIGN KEY (poble) REFERENCES poble(cpo)
        ON DELETE CASCADE
        ON UPDATE CASCADE 
);

Estes són les accions que podem fer en un ON DELETE o en un ON UPDATE:

  • CASCADE: Els registres dependents també s’esborren o es modifiquen.
  • SET NULL: Els registres dependents es posen a null (si no tenien la restricció de NOT NULL).
  • SET DEFAULT: Els registres dependents es posen al valor per defecte (si el tenien). El motor InnoDB ho accepta, però sense cap efecte.
  • RESTRICT: No deixa esborrar/modificar de la taula pare si té registres dependents. És l’opció per defecte (si no posem ON UPDATE o ON DELETE).
  • NO ACTION: En MySQL fa exactament el mateix que RESTRICT.

Exemples amb les taules poble i client:

Exercici pràctic

Per a fer un estudi sobre els tipus de cultius que es donen en cada comarca del món, s'ha creat el següent esquema ER, amb el posterior esquema relacional:

erDiagram
    tipus_cultiu ||--o{ cultivar : "cultiu"
    comarca ||--o{ cultivar : "comarca"
    provincia ||--o{ comarca : "prov + pais"
    pais ||--o{ provincia : "pais"

    tipus_cultiu {
        string codi PK
        string nom
    }

    cultivar {
        string cultiu PK, FK
        string comarca PK, FK
    }

    comarca {
        string codi PK
        string nom
        string prov FK
        string pais FK
    }

    provincia {
        string prov PK
        string pais PK, FK
        int n_hab
    }

    pais {
        string nom PK
        string continent
    }

TIPUS_CULTIU = codi[PK] + nom

CULTIVAR = (cultiu + comarca)[PK]
    FK: cultiu -> TIPUS_CULTIU (codi)
        comarca -> COMARCA (codi)

COMARCA = codi[PK] + nom + prov (NN) + país (NN)
    FK: (prov + país) -> PROVÍNCIA (prov + país)

PROVÍNCIA = (prov + país)[PK] + n_hab
    FK: país -> PAIS (cod)

PAIS = nom[PK] + continent

Indicacions:

  • Abans de crear una taula amb claus alienes, caldrà crear primer les taules de les qual depén. Si no, et donarà error quan intentes crear eixa taula.
  • El codi dels tipus de cultius serà un char(3). El codi de comarques un char(5). La quantitat d'habitants (n_hab) serà un enter. Els altres camps seran un varchar(30).
  • Caldrà indicar les claus alienes de forma que:
    • Si modifiquem el codi d’un país o província en la taula de províncies, també haurà de canviar en la taula de comarques.
    • Si modifiquem un codi de cultiu en la taula tipus_cultius, també s’haurà de modificar en la taula cultivar.
    • Si esborrem un tipus de cultiu en la taula tipus_cultius, també s’hauran d’esborrar els registres de cultivar que tinguen eixe cultiu.
